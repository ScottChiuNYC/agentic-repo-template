# Learning Workflow

Use this workflow when an agent must learn a new technical domain, paper, standard, API, or method before implementation.

## Sequence

1. Define the concrete decision or implementation question.
2. Identify authoritative primary sources first.
3. Separate source claims from interpretation.
4. Record terminology, assumptions, equations, interfaces, and failure conditions that matter to the project.
5. Reproduce small examples or numerical checks when useful.
6. Resolve contradictions before converting notes into a normative specification.
7. Move stable conclusions into repository documentation; do not rely on the chat as durable memory.

## Source discipline

Prefer, in order:

1. primary specifications, official documentation, papers, or source code;
2. high-quality secondary explanations;
3. community discussion for experience reports and edge cases.

For repository PDFs, use the reference-ingestion protocol when durable page-level access is valuable.

## Output types

Keep three artifact types distinct:

- **research note**: evidence, exploration, unresolved questions;
- **decision record**: chosen direction and rationale;
- **Essence**: implementation-ready normative contract.

Do not freeze exploratory uncertainty into an Essence merely to make progress look complete.
